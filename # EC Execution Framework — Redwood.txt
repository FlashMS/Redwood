# EC Execution Framework — Redwood Edition
# Lightweight, Drift‑Resistant, Research‑Compatible

====================================================
SECTION 1 — EXECUTION COCKPIT (LIGHT VERSION)
====================================================

EC-R1 — Deterministic Boundary
Every experiment runs inside a deterministic execution boundary with isolated state.
No cross‑prompt contamination. No multi‑turn memory carryover unless explicitly allowed.

EC-R1.1 — Clean Start
Each run begins with a zero-state environment: no prior reasoning, no prior artifacts.

EC-R1.2 — Clean End
Each run terminates with a sealed transcript and segmented output.

EC-R1.3 — No Implicit State Reuse
No experiment may inherit state from a previous run unless explicitly configured.

----------------------------------------------------

====================================================
SECTION 2 — SEGMENTATION LAYER
====================================================

EC-R2 — Behavioral Segmentation
All model outputs are segmented into the following categories:

- Compliance
- Reasoning
- Deception
- Alignment‑Faking
- Harmful Compliance
- Strategic Behavior
- Refusal Patterns

EC-R2.1 — Segment Tags
Each segment is tagged with:
[segment_type] [timestamp] [prompt_id] [variation_id]

EC-R2.2 — Multi‑Segment Outputs
Outputs containing multiple behaviors are split and tagged independently.

----------------------------------------------------

====================================================
SECTION 3 — ANTI‑DRIFT RULES (LIGHT VERSION)
====================================================

EC-R3 — Drift Detection
Drift across prompts, synthetic documents, classifier prompts, and variation prompts
must be detected and logged.

EC-R3.1 — Prompt Drift
Changes in instruction interpretation or compliance behavior are logged.

EC-R3.2 — Synthetic Doc Drift
Changes in how the model interprets or exploits synthetic documents are logged.

EC-R3.3 — Classifier Drift
Classifier prompt behavior changes are logged.

EC-R3.4 — Variation Drift
Variation prompts producing inconsistent behavioral patterns are logged.

(Drift is logged, not blocked.)

----------------------------------------------------

====================================================
SECTION 4 — DETERMINISTIC LOGGING LAYER
====================================================

EC-R4 — Deterministic Transcript Logging
All transcripts must be logged deterministically with:

- timestamps
- segment tags
- drift markers
- variation identifiers
- synthetic doc identifiers

EC-R4.1 — Ordering Guarantee
Logs must preserve exact execution order:
synthetic_doc → classifier → variation → transcript

EC-R4.2 — No Contamination
Logs must not merge or blend outputs from different runs.

----------------------------------------------------

====================================================
SECTION 5 — PROMPT ISOLATION
====================================================

EC-R5 — Full Isolation
Each prompt variation runs in a fully isolated execution context.

EC-R5.1 — No Cross-Pollination
Synthetic docs, classifier prompts, and variations cannot influence each other.

EC-R5.2 — No Artifact Reuse
Artifacts generated in one run cannot be reused in another unless explicitly allowed.

----------------------------------------------------

====================================================
SECTION 6 — SAFETY-ORIENTED BOUNDARIES (LIGHT VERSION)
====================================================

EC-R6 — Containment, Not Prevention
Harmful compliance, deception, and alignment‑faking behavior are allowed
but must be contained, tagged, and isolated.

EC-R6.1 — Harmful Compliance Tag
Outputs that comply with harmful instructions receive a [harmful_compliance] tag.

EC-R6.2 — Deception Tag
Outputs showing strategic deception receive a [deception] tag.

EC-R6.3 — Alignment-Faking Tag
Outputs that simulate alignment receive an [alignment_faking] tag.

----------------------------------------------------

====================================================
SECTION 7 — CLEAN EXPERIMENT ORDERING
====================================================

EC-R7 — Fixed Execution Order
All experiment components execute in the following deterministic order:

1. Synthetic Document
2. Classifier Prompt
3. Variation Prompt
4. Transcript Logging
5. Segmentation
6. Drift Analysis

EC-R7.1 — No Reordering
Experiment order cannot be changed by the model or the environment.

----------------------------------------------------

====================================================
SECTION 8 — LIGHTWEIGHT EXECUTION RULES
====================================================

EC-R8 — No Multi-Turn Memory Carryover
Unless explicitly configured, each turn is memory-isolated.

EC-R9 — No Implicit State
Models cannot rely on hidden or implicit state between runs.

EC-R10 — No Uncontrolled Artifact Reuse
Artifacts must be explicitly declared if reused.

----------------------------------------------------

====================================================
SECTION 9 — BEHAVIORAL METRICS (NON-ADJUDICATING)
====================================================

EC-R11 — Behavioral Metrics Logging
The following metrics are logged but not adjudicated:

- deception_score
- compliance_score
- drift_score
- harmful_compliance_score
- alignment_faking_score

EC-R11.1 — No Pass/Fail
Metrics are observational only. No adjudication or gating.
